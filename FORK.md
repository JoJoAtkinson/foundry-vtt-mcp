# FORK.md — what this fork changes in upstream files

This is the `pentaryn` fork of [adambdooley/foundry-vtt-mcp](https://github.com/adambdooley/foundry-vtt-mcp).
Everything the fork **adds** lives under `src/fork/` (both packages). This file lists every
place it **edits upstream code**, so a rebase onto a new upstream release knows exactly what it
carries, and so the footprint can trend toward empty: each hunk is either fork wiring that stays
local, or a fix that should go upstream as a PR and then disappear from here.

- Base: upstream `f7e597d` (v0.8.3, merge of PR #70) — `git merge-base HEAD upstream/master`.
- Footprint at `59c781e` (v0.8.3-pentaryn.1): 28 files, +2,718 / −37 — 7 of them under `src/fork/`.
- Gate: `scripts/fork-footprint.sh` lists the upstream files the fork touches and **fails when one
  has no row below**, or when a file's `fork:` marker count differs from the marker table. Run it
  before every commit that touches a file outside `src/fork/`.
- Kind: **local** = fork wiring or fork behaviour, stays here · **PR candidate** = an upstream bug
  or a dnd5e 6 port upstream should take; send it, then delete the hunk and its row.
- New upstream edits: keep them small, mark them with a `// fork:` comment where the language
  allows, add a row here, and prefer moving the logic into `src/fork/` behind one call.
